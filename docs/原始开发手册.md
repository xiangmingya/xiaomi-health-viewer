# 健康数据同步教程：小米运动健康云端 + 动态血糖 Nightscout

两条链路，一份教程。原理一句话：手环/App 把数据推到云，脚本定时从云拉下来。

---

## 一、小米运动健康云端

### 链路

小米手环 → 小米运动健康 App → 小米云 → 拉取脚本 → 本地数据库

注意：数据不是严格实时的。新旧取决于手机 App 最近一次同步上传，想看最新数先打开小米运动健康 App 触发同步。

### 前提

- 小米手环（示例：小米手环 11 国行）
- 手机装小米运动健康 App 并登录小米账号
- Python 3.10+

### 步骤

**1. 安装 SDK**

```bash
pip install mi-fitness
```

这是第三方逆向 SDK，不是小米官方开放 API。好处是能用，代价是小米一改版就可能失效，要跟着修。

**2. 扫码登录**

用 mi-fitness 的扫码登录流程生成二维码（一般 5 分钟有效），用小米运动健康 App 扫码。不需要输入密码。

登录成功后 token 存到本地文件（如 `token.json`），权限设为仅自己可读（`chmod 600`）。token 过期后重新扫一次即可。

**3. 绕开两个坑**

坑一：SDK 默认走 `/app/v1/relatives/*`（查亲友数据），查自己的 uid 会报 `FamilyMemberNotFoundError(-4002001)`。解决办法是在运行时把 `mi_fitness.client.data` 模块的三个路径 patch 到 `/app/v1/data/*`：

- `RELATIVES_AGGREGATED_DATA_PATH`
- `RELATIVES_LATEST_DATA_PATH`
- `RELATIVES_FITNESS_DATA_PATH`

注意 patch 的是 `data` 模块，不是 `const`。

坑二：如果机器有代理环境变量，且 `NO_PROXY` 里写了方括号 IPv6（如 `[::1]`），httpx 会报 `Invalid port: ':1]'`。在进程内覆写即可，不要动全局环境：

```bash
NO_PROXY='localhost,127.0.0.1,::1'
```

**4. 拉取数据**

```python
client = MiHealthClient.from_token("token.json")
steps = await client.get_daily_summary(uid, date)  # 步数/距离/热量汇总
spo2  = await client.get_spo2_history(uid, date)    # 血氧
sleep = await client.get_sleep(uid, date)           # 睡眠
# 心率等见 client 上的 get_* 方法
```

建议落地到本地 SQLite，方便按天查询（比如一张 `daily_metrics` 表存日期、步数、心率、血氧）。

**5. 定时同步**

设 cron/计划任务每天早上同步最近 3 天。同步成功静默，token 失效时再提醒扫码。

### 能拿到什么

步数、距离、活动热量、心率（平均/静息/最高/最低）、血氧（平均/最高/最低/最新）、睡眠、运动记录。实测比 Health Connect 中转更快更全。

## 二、动态血糖 Nightscout

### 链路

动态血糖仪（如欧态 M8 CGM）→ 配套 App → Nightscout 服务端 → 读取脚本

### 前提

- 支持 Nightscout 上传的动态血糖仪 App
- 自建 Nightscout 服务（比如在自己的 NAS 或云服务器上用 Docker 部署）
- 记住你设置的 API_SECRET

### 步骤

**1. App 端配置上传**

在血糖仪 App 里填入你的 Nightscout 地址和 API_SECRET。填完后观察服务端是否有数据流入。

**2. 读取数据（两个坑）**

坑一：Nightscout API 只认 API_SECRET 的 SHA-1 哈希，不认明文。请求头示例：

```
api-secret: <sha1(API_SECRET)>
```

坑二：如果服务端前面有 Cloudflare Bot Fight Mode，没有浏览器 User-Agent 的请求会被 403。请求时带上：

```
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 ...
```

凭据不要写进代码，放进密钥管理工具或环境变量，脚本运行时动态取用。

读取接口：

```
GET /api/v1/entries/sgv.json?count=288
```

返回值单位是 mg/dL，除以 18.01559 得 mmol/L。

**3. 断传处理**

如果发现上传中断（比如几小时没新数据）：

1. 先打开血糖仪 App——App 会把本地积压的数据自动补传到 Nightscout，大断档一般这样就好了。
2. 如果还有小断档（十几二十分钟），从 App 导出数据表格，用 `POST /api/v1/entries` 把缺的几笔手动推进去。注意 sgv 要换算成 mg/dL 的整数，`date` 用毫秒时间戳，别和已有数据重复。

**4. 定时任务**

- 每天早上拉过去 24 小时数据，算平均血糖、TIR、最高最低、凌晨 3–8 点黎明现象，生成晨间小结。
- 可选：每晚检查一次上传，最新数据距今超过 2 小时才提醒打开 App，否则静默。

### 安卓保活说明

以原生安卓（如索尼）为例，系统没有国产 ROM 那种激进的杀后台。如果断传，更可能是 App 自身崩溃或被点了"强制停止"，而不是系统清理。注意：

- 把血糖仪 App 设为电池优化白名单（设置–电池）。
- 不要去应用信息里点"强制停止"。
- 开发者选项里"后台进程限制"保持标准。
